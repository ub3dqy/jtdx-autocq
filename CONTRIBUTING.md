# Помочь AutoCQ / Contributing

Нашли ошибку во время работы? Нажмите **«Сообщить об ошибке»** в AutoCQ. Поддержка принимает описание и диагностику за предыдущие 20 минут без регистрации. Если у вас есть аккаунт GitHub, вы можете открыть черновик Issue с описанием и номером отчёта. [Как отправить отчёт](USER-GUIDE.md)

Можно также [создать Issue вручную](https://github.com/ub3dqy/jtdx-autocq/issues/new/choose). Напишите версию AutoCQ, настройки и последовательность действий. Для ошибки в эфире укажите время события и часовой пояс.

Есть идея новой функции? Для конкретного предложения используйте форму **«Предложение»** в Issues. Если хотите сначала обсудить варианты или задать вопрос, откройте [Discussions](https://github.com/ub3dqy/jtdx-autocq/discussions).

Проверяйте вложения перед публикацией. Нам не нужны полные профили JTDX и LogHX, файлы авторизации или личные данные. Для примера обычно достаточно нескольких строк вокруг нужного события.

Если хотите предложить изменение кода, сделайте fork, внесите правку в отдельной ветке и откройте pull request. Опишите, какую задачу решает изменение и как вы его проверили. Для новых функций обновите оба README, руководства и снимки изменившихся окон. Проверки запускаются командой `build.ps1 -Test`; подробности сборки есть в README.

## English

Found a bug while using AutoCQ? Click **«Сообщить об ошибке»** (Report a bug). You can send your description and the preceding 20 minutes of diagnostics to support without signing up. If you have a GitHub account, you can open an issue draft with your description and report number. [How to send a report](USER-GUIDE.en.md)

You can also [create an issue manually](https://github.com/ub3dqy/jtdx-autocq/issues/new/choose). Include your AutoCQ version, settings and the steps needed to reproduce it. For an on-air event, give its time and time zone.

For a specific feature idea, use the **Feature request** form in Issues. For questions, setup help or an open-ended discussion, use [Discussions](https://github.com/ub3dqy/jtdx-autocq/discussions).

Check attachments before posting. Full JTDX or LogHX profiles, authentication files and personal information are not needed. A few relevant log lines are usually enough.

Code contributions are welcome through a fork and pull request. Explain the problem, your change and how you checked it. Update both READMEs, user guides and screenshots for new features. Run `build.ps1 -Test`; see the README for build instructions.
